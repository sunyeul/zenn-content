## はじめに

キャンペーン後に売上が増えた。その増加のうち、キャンペーンがなくても起きていた分はどのくらいでしょうか。

[CausalImpact](https://google.github.io/CausalImpact/CausalImpact.html)は、介入前の結果と、介入の影響を受けない対照時系列から「介入がなかった場合」を予測し、観測値との差を調べる方法です。そこで使う予測器に、事前学習済みの時系列モデルを使えたら便利そうです。

[TimesFM 3](https://research.google/blog/timesfm-3-a-zero-shot-foundation-model-for-multivariate-forecasting/)なら、追加学習なしに対照時系列を渡し、先の区間をまとめて予測できます。反実仮想の予測器を試すハードルが下がるのはうれしいところ。

ただ、**予測が外れた分も、観測値との差に入ります。** 施策を何もしていなくても、「効果あり」に見えてしまうかもしれません。

そこで、答えが分かる合成データで試します。「効果なし」で差がどれだけ残るか。「効果あり」では、加えた分をどれだけ取り戻せるか。この2つを、次の順に確かめます。

- **Part A：予測器に共通する検証。** 過去の予測、時間A/A、既知の効果の注入を通じて、知りたい効果を誤差と区別できそうかを確認します。
- **Part B：TimesFMを使う実益。** 対照時系列の有無を比べ、追加学習なしの予測が今回の目的に役立つかを見ます。
- **Part C：固定した設定で効果を計算。** 前の検証で分かった精度と限界を踏まえ、介入後の差と累積効果を読みます。

最後に、同じ条件のBSTSとも比較します。予測器を変えると何が違うのか、区間の作り方まで含めて見ていきます。

TimesFM 3の基本的な使い方や、関連データ・予定を加える予測は、前の記事で試しています。今回はそこから、予測を介入効果の分析に使う前の検証へ進みます。

## まず、何を「効果」として計算するのか

### 観測値から「介入がなかった場合」を引く

介入がなかった場合の結果を $Y_t(0)$、その予測を $\hat Y_t(0)$ とすると、計算する差は次の形です。

$$
\hat\tau_t = Y_t^{\mathrm{obs}}-\hat Y_t(0)
$$

たとえば観測値が110、介入がなかった場合の予測が100なら、差は10です。ただし、その予測自体が10だけ低く外れていたなら、介入なしでも同じ差が出ます。

この差を因果効果として解釈するには、対照時系列が介入の影響を受けず、介入がない場合の関係を予測区間へ持ち越せることが必要です。[CausalImpactの公式説明](https://google.github.io/CausalImpact/CausalImpact.html)でも、この2点が前提になっています。同時期の別の変化や、介入前からの先行反応も確認したいところです。

TimesFMが直接返すのは、渡した情報に条件づけた予測です。観測値との差を取っただけで因果関係が確定するわけではありません。まずは **条件付き予測との差（Conditional Forecast Difference）** として読み、因果仮定と検証を併せて考えます。

### 今回は、真値が分かる合成データで試す

データは「ゆっくり変わる基礎水準 + 2本の対照時系列の線形な影響 + ノイズ」で作ります。

$$
\begin{aligned}
\mu_t &= \mu_{t-1}+\eta_t,\\
Y_t(0) &= \mu_t+1.4X_{1,t}-0.9X_{2,t}+\epsilon_t.
\end{aligned}
$$

対照時系列には周期的な動きがあり、介入の影響は加えません。結果変数については、同じ $Y(0)$ から「効果なし」と「介入後に10%上昇」の2つを作ります。

```python
effect_none = np.zeros(TOTAL, dtype=np.float32)

effect_positive = np.zeros(TOTAL, dtype=np.float32)
effect_positive[PRE:] = 0.10 * y0[PRE:]

y_null = y0 + effect_none
y_treated = y0 + effect_positive
```

`y_null` が効果なし、`y_treated` が効果ありの系列です。冒頭の図では観測値と真の $Y(0)$ を重ね、その下に対照時系列を表示します。ここで、**効果を加えたのは結果変数だけ**という対応を確認できます。

この構造はBSTSのlocal levelと回帰モデルで表現しやすい例です。CausalImpactの原論文のシミュレーションをそのまま再現したものでも、モデルの一般的な優劣を決めるデータでもありません。

## Part A：効果を読む前の共通検証

ここからの検証は、TimesFM以外の予測器でも必要です。まずモデルと入力を固定して、予測の誤差が効果の読み方にどう響くかを見ます。

### 1. 過去を予測すると、どこで外れる？

TimesFMには、結果変数の過去と、予測区間まで含む対照時系列を渡します。ノートブックの予測関数は、介入後の実際のYを戻さず、一度に指定した長さを予測します。

```python
def run_counterfactual(model, y_context, horizon, covariates=None):
    """One-shot H-step forecast. Post-period target Y is never fed back."""
    y_context = np.asarray(y_context, dtype=np.float32)[None, :]

    kwargs = dict(
        context=y_context,
        horizon=horizon,
        return_quantiles=True,
        use_symmetric_averaging=False,
        make_positive=False,
    )

    if covariates is not None:
        kwargs["past_future_covariates"] = np.asarray(
            covariates, dtype=np.float32
        )

    out = model.predict(**kwargs)

    forecast = np.asarray(out.forecast)
    quantiles = np.asarray(out.quantiles)

    if forecast.ndim == 2:
        forecast = forecast[0]
    if quantiles.ndim == 3:
        quantiles = quantiles[0]

    return forecast, quantiles
```

`past_future_covariates` に渡すのは、介入の影響を受けない対照時系列です。たとえば入力が256時点、予測が64時点なら、対照時系列は両方を含む320時点分を用意します。

予測開始時点を16ずつずらしながら、同じ処理を繰り返します。

```python
CONTEXT = 256
DEV_H = H
FINAL_AA_CUT = PRE - H

# Overlapping windows are descriptive diagnostics, not independent trials.
DEV_CUTS = np.arange(
    CONTEXT,
    FINAL_AA_CUT - DEV_H + 1,
    16,
    dtype=int,
)
```

この設定では開始時点が256、272、…、384の9ウィンドウになります。どれも64時点を予測するので、評価区間は互いに重なります。

ノートブックでは各ウィンドウの観測値と予測値、MAE、平均符号付き誤差（ME）、16時点ずつに分けたMAEが出ます。

$$
e_{k,h}=Y_{k,h}-\hat Y_{k,h}(0),\qquad
\mathrm{MAE}_k=\frac{1}{H}\sum_h|e_{k,h}|,\qquad
\mathrm{ME}_k=\frac{1}{H}\sum_he_{k,h}.
$$

下の図でMAEとMEを見比べ、外れ方が気になるウィンドウは、折りたたみ内の予測経路で線の形を確認します。読み方の目安は次のとおりです。

| 出力がこう見えたら | 何を確認するか |
|---|---|
| 動きは似ているが、予測線がずっと下にある | 水準を低く予測しています。MEが正になり、その差が累積しないかを見ます。 |
| MEは0に近いのにMAEが大きい | 正負の誤差が相殺されているかもしれません。毎時点の予測が正確とは限りません。 |
| 一部のウィンドウだけ外れる | どの時期から線が離れるかを見ます。全体平均だけでは時期による違いが隠れます。 |
| 予測後半のMAEが大きい | 評価したい期間の最後まで、必要な精度を保てているかを確認します。 |

#### MAEが小さければ、それで十分？

説明用に、1日の平均結果が100、MAEが2のケースを考えます。誤差は普段の水準の2%ですが、知りたい変化が1日+1なら、その誤差は小さくありません。

さらに、毎日+2ずつ同じ方向に外れると、64日間の累積誤差は+128です。+2と−2が交互なら、MAEは同じでも累積誤差は0になり得ます。

**1時点の誤差の大きさと、期間全体の偏りは別々に見る必要があります。** 次は、その累積した差を直接確認します。

なお、表にある `MAE / 観測平均 (%)` は規模を読むための比率で、MAPEではありません。結果が0付近だったり正負を行き来したりするデータには、そのまま使わないでください。

### 2. 何もしていない過去でも「効果」は出る？

過去の未介入区間を「ここで介入したことにする」と考え、観測値から予測値を引きます。これが時間プラセボ検証（in-time placebo）です。ノートブックでは時間A/Aと呼んでいます。無作為に分けた2群の比較とは異なります。

真の効果は0なので、64時点の差の合計は、予測誤差から生まれた**見かけの累積効果**です。

$$
E_k=\sum_{h=1}^{H}e_{k,h}=H\,\mathrm{ME}_k.
$$

この過去の累積誤差から、共通の偏りと、そこからどれだけ外れるかを求めます。

```python
def empirical_error_band(values, level=0.90):
    """
    Cumulative error distribution -> bias and symmetric error radius.
    Diagnostic only; not a formal conformal guarantee.
    """
    values = np.asarray(values, dtype=float)
    bias = np.median(values)
    radius = np.quantile(np.abs(values - bias), level)
    return bias, radius
```

`bias` は累積誤差の中央値、`radius` はその中央値からの絶対偏差の90%分位点です。見かけの効果から `bias` を引き、補正後の点の両側に `radius` を付けます。

各開発ウィンドウを評価するときは、評価対象のウィンドウを除いて補正値を計算します。

```python
def leave_one_out_band(values, i, level=0.90):
    others = np.delete(np.asarray(values, dtype=float), i)
    return empirical_error_band(others, level=level)
```

出力の `aa_result` は元の単位での点と区間、`aa_scale` は観測合計に対する割合です。図では0を含む区間が青、含まない区間が赤になります。

- **赤い区間が繰り返される**なら、介入なしでも効果があると読んでしまう可能性があります。
- **点が0付近でも区間が広い**なら、小さな効果との区別が難しいかもしれません。
- **開始時点ごとに正負が入れ替わる**なら、共通のバイアス補正がすべての時期に合うとは限りません。

ここでの90%は、誤差半径を作るときの分位点の設定です。**実際に90%の被覆率を持つ区間と保証しているわけではありません。** ウィンドウを1つ除いても残りと日付が重なるため、0を含まない割合も、独立した実験から推定した偽陽性率とは扱いません。

#### 累積誤差300は、大きいのか？

1日平均100、期間64日のケースを考えます。介入がない場合の合計は6,400。累積誤差300は1日平均約4.69、期間合計の約4.69%になります。

| 知りたい効果 | 64日間の効果量 | 累積誤差300との関係 |
|---|---:|---|
| +2% | 128 | 誤差が効果の約2.34倍 |
| +5% | 320 | 誤差が効果の約94% |
| +10% | 640 | 誤差が効果の約47% |

同じ300でも、知りたい効果によって意味が変わります。**累積誤差が同じなら、真の効果が小さいほど、予測のズレとの区別は難しくなります。**

点の位置と区間の幅も分けて読んでください。補正後の点が+10、区間が−290〜+310なら、点は0に近くても、誤差半径は300、全幅は600です。「0を含んだ」だけでは、小さな効果を読めるとは言えません。

### 3. 知りたい大きさの効果を加えてみる

A/Aで0を含みやすい区間が作れたとしても、広すぎれば本当の効果まで見逃します。そこで、未介入の結果変数だけに+2%、+5%、+10%の持続的な効果を加えます。

ループの中で行う計算は次の部分です。対照時系列と過去の入力は変わらないので、元の予測をそのまま使えます。

```python
injected = untreated * (1 + lift)
true_effect_path = injected - untreated
estimated_effect_path = injected - forecast
```

同じA/A補正を適用した後、`injection_summary` で、加えた効果と推定した効果、平均絶対相対誤差、検出率を確認します。

相対誤差の分母は、**加えた効果そのもの**です。真の効果が300なのに240と推定したら、絶対相対誤差は20%。普段の結果の水準に対する誤差率とは意味が違います。

大きな効果は検出できても、+2%だけ難しいなら、知りたい効果量に対して誤差や区間が大きい可能性があります。逆に検出率が高くても、推定した大きさが大きく外れるなら、効果量の推定には課題が残ります。

ここは**効果の有無と、大きさの復元を分けて読む**ところです。平均推定値が真値に近くても、ウィンドウごとの過大・過小推定が相殺されていないか、相対誤差も見てください。

本文の検出率は「方向を問わず区間が0を含まない割合」です。正の効果を加えているので、推定の方向も併せて確認します。また、本文の検出率と相対誤差は0〜1の比率で、0.2なら20%です。

この結果は、重なるウィンドウに一定割合の効果を加えた場合の感度点検です。独立した実験の検出力や、別の効果の形に対する性能まで示すものではありません。

## Part B：対照時系列を渡すと、予測はよくなる？

Part Aでは、対照時系列を使う構成を固定し、その誤差で効果を読めそうかを確かめました。ここでは開発区間に戻り、そもそも対照時系列を加えることで、予測がどれだけ変わるかを見ます。

TimesFM 3では、事前学習済みモデルに対照時系列を直接渡せます。今回のように開始時点を変えて何度も検証するとき、時点ごとにモデルを追加学習せず試せるのが便利です。

ただ、対照時系列を入力できることと、実際に役立つことは別です。同じ開発ウィンドウで、対照時系列なしの予測も作ります。

```python
# Assess the value of controls separately from Part A's fixed-model validation.
univariate_mae = []
for i, cut in enumerate(DEV_CUTS):
    forecast_no_cov, _ = run_counterfactual(
        forecaster,
        y_context=y0[cut - CONTEXT:cut],
        horizon=DEV_H,
        covariates=None,
    )
    univariate_mae.append(np.mean(np.abs(actual_paths[i] - forecast_no_cov)))
```

`control_comparison` の表と線グラフで、対照あり・なしのMAEをウィンドウごとに比べます。

対照ありのMAEが複数のウィンドウで一貫して小さければ、そのデータと設定では追加情報が予測に寄与する根拠になります。改善が小さい、あるいは時期によって逆転するなら、使う実益は限定的かもしれません。誤差が増える場合は、変数の関連性や時点の対応も点検します。

もう1つ見るのが、Part Aの予測後半のMAEです。64時点を一度に出せても、後半で精度が崩れるなら、長い効果評価にはそのまま使いにくくなります。

ここで入力構成を変更するなら、変更後の構成で検証・補正をやり直します。すでに見た最終A/Aを、新しい構成の独立した最終確認として使い回すことはできません。

## Part C：固定した設定で効果を計算する

### 時点別の差と、補正後の総効果を分ける

合成データの介入後64時点を、同じ設定で分析します。ここでも入力するYは介入前までです。

```python
real_start = PRE - CONTEXT
real_covariates = controls[:, real_start:PRE + H]

real_cf, real_q = run_counterfactual(
    forecaster,
    y_context=y_treated[real_start:PRE],
    horizon=H,
    covariates=real_covariates,
)

observed_post = y_treated[PRE:]
estimated_effect = observed_post - real_cf
real_cumulative = float(estimated_effect.sum())

real_corrected = real_cumulative - dev_bias
real_lower = real_corrected - dev_radius
real_upper = real_corrected + dev_radius
```

ここで見たいのは、差がいつ生まれたかと、期間全体でどれくらい残ったかです。図を分けて確認します。

- 観測値と反実仮想予測、時点別の差、累積した差の経路
- 期間全体の効果について、補正前の最終値と補正後の点・経験的区間を並べた図

経路図は補正前の値です。今回は64時点の累積誤差だけを補正しているため、その補正を日別に割り振ったり、途中時点の区間へ広げたりはしません。

補正前後で最終値が大きく動くなら、過去の累積バイアスが結論に強く影響しています。その偏りが今回の区間にも当てはまりそうかを考えます。

経験的区間が0を含むなら、現在の誤差範囲では0と区別できません。含まない場合も、因果仮定や開発A/Aの問題まで解決したわけではありません。前の検証で残った限界を、そのまま持ち込んで読みます。

### p10–p90は、累積効果の区間ではない

予測図には、TimesFMが返す時点別のp10–p90も表示します。これは各時点の予測分位点の範囲です。名目上は中央80%に対応しますが、実際の被覆率は別途検証が必要です。

これを単純に足して、64時点の累積効果の区間にすることはできません。合計の不確実性には、時点間で誤差がどう一緒に動くかも関わるからです。

今回の経験的区間は、過去の**64時点の誤差を先に合計した値**から作っています。時点別の予測分位点とは、材料も目的も違います。

### 真値との照合は、最後の答え合わせ

合成データでは真の $Y(0)$ と加えた効果が分かるので、`positive_summary` と `null_summary` で累積効果やMAEを照合できます。

- 真の累積効果が区間内に入ったか
- 加えた10%の効果を、どのくらい近く復元できたか
- 効果なしのケースで、見かけの効果がどのくらい残ったか

これは今回の合成例での答え合わせです。2つのケースは同じ介入前の結果と対照時系列を使っており、独立した2回の検証ではありません。

実データでは真値が分からないので、知りたい累積効果の大きさを先に決め、推定値と区間の半径をそこに照らします。効果を%で表す場合も、分母となる「介入がなかった場合の合計」は推定値です。介入後の観測合計には効果が含まれるため、A/Aと同じ感覚で基準にしないようにします。

## BSTSと比べるときは、予測器と区間を分ける

ここまでの累積誤差や区間の幅は、予測モデルを変えるとどうなるでしょうか。さらに、同じ予測モデルでも、区間の作り方によって効果の読み方は変わるでしょうか。

この2つを分けて確かめるため、ノートブックの付録では、RのCausalImpactが使うベイズ構造時系列モデル（BSTS）を同じデータに適用します。

本文を実行したPythonランタイムからRを別プロセスで動かすので、ランタイムの切り替えは不要です。初回のパッケージ準備には時間がかかることがあり、BSTSの計算はCPUで行います。

### 比較条件をそろえる

入力長256、予測長64、2本の対照時系列、予測開始時点をTimesFMとそろえます。BSTSは各開始時点で学習し直し、予測区間の結果は学習に使いません。

付録ではMCMC反復数を4,000、`prior.level.sd` を0.01に固定しています。基礎水準と固定の回帰係数を使い、追加の季節成分は入れません。今回は対照変数が周期的な動きを持っているためです。

`prior.level.sd=0.01` は[CausalImpactのデフォルト値](https://google.github.io/CausalImpact/CausalImpact.html)ですが、このデータに最適な設定という意味ではありません。シードや反復数に対する安定性、MCMCの収束も別途確認が必要です。

まずは `bsts_comparison` でMAEと補正前の累積誤差を比べます。これで、どちらの予測器がどのウィンドウで外れたのかを見られます。その後で区間の比較へ進みます。

### 区間の作り方も含めて、3つの効果推定方式を比べる

ここまでは、TimesFMとBSTSの予測誤差を比べました。次は、その予測から効果の点推定と区間をどう作るかを比べます。

まず両モデルに、過去の累積誤差から作る経験的補正を適用します。さらにBSTSでは、モデル自体の事後分布を使う方法も確認します。**予測モデルは2つ、比較する効果推定方式は3つ**という組み合わせです。

| 表示される方法 | 点推定と区間の作り方 | 比較で分かること |
|---|---|---|
| `TimesFM + empirical` | TimesFM予測に、過去の累積誤差による補正を適用 | 本文の方法 |
| `BSTS + empirical` | BSTS予測に、同じ手順で求めたBSTS側の補正を適用 | 経験的な区間の作り方をそろえ、予測器を変えた差 |
| `BSTS native` | BSTS自体の事後分布から点と区間を計算 | 予測器と不確実性の計算を組み合わせた結果 |

「同じ経験的補正」とは、同じ数値を使うという意味ではありません。各モデルの過去の累積誤差から、それぞれバイアスと半径を求めます。

BSTS自体の区間には、経験的バイアス補正を追加しません。[公式実装](https://github.com/google/CausalImpact/blob/master/R/impact_inference.R)では、予測サンプルの経路を累積してから区間を求めています。時点別の区間を単純に足したものではありません。

付録ではBSTSの事後区間を90%に設定し、経験的補正にも0.90を使います。ただし、同じ数字でも同じ被覆保証を意味しない点は、ここでも変わりません。

## おわりに

TimesFM 3で施策の効果は測れるのか。反実仮想の予測を作り、観測値との差を計算するところまでは試せます。その差を効果として読めるかは、別の確認が必要です。

その判断では、次の3点を押さえます。

- **効果の大きさを、累積誤差と比べる。** 同じ誤差でも、知りたい効果が小さいほど区別は難しくなります。
- **効果を検出できることと、大きさを正確に推定できることを分ける。** A/Aと効果注入を併せて、見かけの効果と見逃し、推定量のズレを確認します。
- **予測モデルと区間の作り方を分けて評価する。** MAEが小さいことや区間が狭いことだけでは、効果推定に向いているとは決められません。

TimesFM 3は、対照時系列を含む反実仮想予測を追加学習なしに試す入口になります。実務で使う判断には、そこで得られた予測精度だけでなく、累積誤差、区間の幅、因果仮定までが関わります。

ノートブックを試すなら、まず自分が知りたい変化を+2%なのか+10%なのか決めて、その行をA/Aと効果注入の両方で読んでみてください。「予測がよく当たる」から一歩進んで、**その精度で、知りたい効果を読めそうか**を考えるための検証です。
