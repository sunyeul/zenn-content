# Meet Flow — PRD

更新日: 2026-11-04

Google Meetの新しいチャットを、発表者が見ているWebタブに重ねて表示するChrome拡張のプロダクト要求仕様書です。利用場面、機能、操作、データの扱い、受け入れ条件を定義します。

## 1. 解決したい課題

社内勉強会などで発表していると、オンライン参加者の反応を拾いにくくなります。参加者はチャットで短い感想を書けても、発表者は説明中のWebページやWebアプリから視線を移さないと気づけません。

Meet Flowの目的は、「なるほど」「わかる」といった新しい反応を、発表者が見ている画面へ届けることです。チャットの全履歴を読むことや、参加者同士の会話を置き換えることは目的に含めません。

## 2. 想定する利用者と場面

主な利用者は、Google Meetを併用し、WebページやWebアプリを見せながら説明する人です。参加者は通常のMeetチャットへ投稿し、Meet Flowを導入する必要はありません。

発表者は一つのブラウザプロファイルで、一つの収集元Meetと一つの表示先タブを指定します。表示先は別のWebタブでも、収集元と同じMeetタブでも構いません。

参加者にもコメントを見せる場合は、発表者がMeetの画面共有を別途開始します。拡張の表示先指定とMeetの共有対象指定は独立しています。表示テストが成功しただけでは、参加者側に見えているとは判断しません。

## 3. 対象範囲

| 対象 | 対象外 |
| --- | --- |
| 選択したMeetの最上位文書に表示されるチャット | Slack、Google Chatタブ・子iframe内のチャット、複数会議の同時収集 |
| HTTP/HTTPSのWebタブへの表示 | PowerPointなどのデスクトップアプリ、OS全体、ブラウザ内部ページへの表示 |
| 流れるコメント、右下チャットの二つの表示モード | 音声認識、翻訳、AI要約、投稿モデレーション |
| 収集開始、表示先指定、表示テスト、全体停止、状態確認 | チャット投稿・編集・削除、添付ファイルやプロフィール画像の表示 |
| セッション内の状態管理と重複除外 | 本文の保存・検索・履歴再生、外部サーバーへの同期 |

画面共有の自動開始、共有対象の自動判定、参加者全員への直接配信は行いません。基本機能の利用に外部サービスやAPIキーを要求しません。

## 4. 基本の操作フロー

1. 発表者がMeetのチャットパネルを開く。
2. 拡張のポップアップで収集元Meetを選び、収集を開始する。一覧にない場合は、そのMeetタブで「現在のタブをMeetに指定」を使う。
3. 表示したいWebタブへ移動し、拡張を開いて「現在のタブを表示先に確定」を押す。
4. 「表示テスト」で表示経路を確認し、別の参加者の新しい投稿でも収集から表示までを確認する。
5. 必要に応じて表示モードを切り替える。参加者にも見せる場合は画面共有を開始し、受信側でも確認する。
6. 発表終了時に「全体停止」を押す。

表示先の確定と表示テストは、収集開始前にも実行できます。収集を開始すると表示先はいったん解除されます。同じMeetの同じ文書で収集を再開始する場合に限り、到達確認できた既存表示先を維持します。ポップアップを閉じても収集・表示は続きます。

## 5. 機能要件

以下を基本機能とします。表示の数値は既定値です。

### 5.1 収集元と表示先

| ID | 要求する動作 |
| --- | --- |
| F01 | 利用者が明示的に収集を開始するまで本文を監視しない。選んだMeetの最上位文書だけを収集する。 |
| F02 | 手動指定でも現在のタブがHTTPSの`meet.google.com`であることを確認する。独立Chatや別サイトからの収集を許可しない。 |
| F03 | 表示先は、そのタブで拡張を操作して確定する。他のタブへフォーカスを移しても表示先を変えない。 |
| F04 | 新しい表示先への接続を確認してから切り替える。接続できない場合は、既存の表示先を維持して失敗を知らせる。 |
| F05 | 表示先を指定していない期間の本文は蓄積せず、後から一括表示しない。 |
| F06 | 表示テストは確定した表示先へ送り、実チャットの収集成功とは区別して案内する。 |

### 5.2 収集対象と新規投稿の判定

最上位文書のチャットパネルに表示される、本文とメッセージIDを持つ投稿を対象にします。初回走査の既存投稿は除外し、その後のDOM変更で確定投稿を検出します。投稿時刻の比較や子iframeの巡回は行いません。

| ID | 動作 |
| --- | --- |
| F07 | 収集開始時に存在する確定投稿を処理済みとして記録し、表示しない。 |
| F08 | `data-pending="true"`配下の投稿は確定待ちとして保留する。確定後のDOM置換と、同じ要素のpending解除の両方を再走査する。 |
| F09 | 最寄り祖先の`data-message-id`を必須とする。IDがない投稿は表示せず、本文や表示位置から代替IDを作らない。 |
| F10 | 要素とIDで重複を除外し、同じ本文でも異なるIDの確定投稿は別々に扱う。セッション領域には直近5,000 IDを保持し、停止・再開始で初期化する。 |
| F11 | 空本文は表示しない。同じ要素・同じIDの本文編集やリアクション更新で再表示しない。収集イベントのセッション識別値が現在の収集と異なる場合は受け付けない。 |

開始後に読み込まれた過去記録は、新規投稿と区別できない場合があります。開始前から存在した未確定投稿も、開始後に確定すれば表示候補になります。

本文は前後の空白を除き、最大500 UTF-16コード単位のプレーンテキストとして扱います。見た目上の500文字とは一致しない場合があります。直近5,000 IDの保持範囲を超えた重複防止や、すべての投稿を一度だけ確実に表示することは保証しません。表示先未指定・配送失敗・待ち行列超過で失われた投稿の自動再送・履歴再生は行いません。

### 5.3 表示モード

| 項目 | 流れるコメント（初期モード） | 右下チャット |
| --- | --- | --- |
| 表示 | 右端の外から入り、左端の外まで等速で流す | 新しい投稿を下に追加し、既存の投稿を上へ送る |
| 領域 | 画面上部の約70% | 画面右下の透明な表示面 |
| 件数・時間 | 1〜8レーン、1件4.5秒 | 最新6件、各20秒。最後の2秒はフェードアウト |
| 名前 | 本文のみ | 「名前: 本文」。取得できなければ「参加者」などを使う |
| 読みやすさ | 白い太字に暗い縁取りと影、1行表示 | 名前は色分けし、本文は白と暗い縁取り。長文は最大3行 |

流れるモードの待ち行列はFIFOで最大200件とし、表示中のコメントとは別に数えます。超過した新規投稿は表示せず、接続障害とは区別して知らせます。右下モードでは6件を超える最古の行が上へ移動しながら消え、新規追加時の移動時間は280msです。右下の余白は24px、下の余白は28px、最大幅は440pxかつ画面幅から32pxを引いた値以下、表示領域の高さは画面高の65%です。名前は最大100 UTF-16コード単位で、同じ名前には同じ色を使います。

モード変更、表示先変更、全体停止では、以前の表示と待ち行列を消します。表示テストにも選択中のモードを適用します。表示面は元のページへのクリックを妨げず、キーボードフォーカスを奪わないようにします。ウィンドウのリサイズでも表示と待ち行列を消去します。文字サイズ・速度・色の設定UIは設けません。

### 5.4 状態変更と復旧

| イベント | 期待する動作 |
| --- | --- |
| 収集元を閉じる、再読み込みする、別の会議・ページへ移動する | 全体停止し、収集元の再指定を案内 |
| 表示先だけを閉じる、再読み込みする、別ページへ移動する | 表示先だけを解除し、収集は維持 |
| 同じタブが収集元と表示先を兼ねた状態で無効になる | 収集元側のルールを優先し、全体停止 |
| 無関係なタブの切り替え・終了 | 収集・表示の設定を変えない |
| 配送先との接続に失敗する | 表示先を解除し、再指定を案内 |
| 全画面へ移る、全画面を解除する | 表示面の再接続を試みる。接続回復時に期限切れの投稿を再生しない |
| 全体停止 | 収集を無効にし、表示と待ち行列の消去を要求。重複除外IDを解除 |

同じURLでも文書が再読み込みされたら接続を再指定します。文書が変わらず、クエリやフラグメントだけが変わった場合は、原則として別ページへの移動とは扱いません。

応答待ちには上限を設け、無応答によって後続操作が永久に止まらないようにします。停止前の古い処理で有効状態を復活させてはいけません。ただし、タイムアウトだけで応答のないタブから表示を消せたとは判断しません。

## 6. 権限とデータの扱い

Chrome Manifest V3、Chrome 106以降を対象とします。権限は`activeTab`・`scripting`・`storage`と、`https://meet.google.com/*`へのホストアクセスです。`chat.google.com`や全サイトへの常時アクセスは要求しません。表示先はそのタブで得た`activeTab`の一時アクセスを使います。

本文と発言者名は処理中のメモリと表示用DOMで扱い、拡張のストレージ・分析イベント・URLには保存せず、外部サーバーへ送信しません。選択したタブ、表示モード、接続状態、重複除外用IDなどは`storage.session`に保持します。

診断ログはブラウザのコンソールに出力します。本文の先頭80 UTF-16コード単位、メッセージID、文書URL、対象要素と祖先の属性、DOM断片を含みます。DOM断片には本文や発言者名が含まれ得ます。

表示先サイトのスクリプトから本文DOMを直接読まれないよう、拡張オリジンのiframe内で描画し、本文は専用の通信経路で渡します。親ページのDOM・属性・iframe URL・ページから見えるwindowメッセージへ本文を入れません。HTMLのような本文や名前も文字列として表示します。接続に失敗しても親ページへ直接描画する方式に切り替えません。

収集元・会議・文書と表示先の対応を検証し、選択していない会議の本文や、移動後の別ページへ配送しないようにします。Webページから収集開始や表示先変更などの設定操作を受け付けません。

この隔離は、画面共有・録画・スクリーンショットへの写り込みを防ぐものではありません。表示先ページによるiframeの削除や非表示、高い権限を持つ他の拡張やOSからの取得も防御範囲外です。

## 7. 状態の伝え方

ポップアップは「①チャット収集」「②コメント表示」の二段構成とし、現在のタブ、収集元、表示先、表示モードを示します。Meet一覧からの開始と、現在のMeetを手動指定する操作を備えます。UI言語は日本語・韓国語です。

| 設定状態 | ポップアップの収集灯（左） | ポップアップの表示灯（右） | ツールバーアイコン |
| --- | --- | --- | --- |
| 停止・表示先なし | 消灯 | 消灯 | 停止（グレー・両灯消灯） |
| 収集停止・表示先のみ確定 | 消灯 | 点灯 | 停止（グレー・両灯消灯） |
| 収集中・表示先なし | 点灯 | 消灯 | 収集（グレー・左点灯） |
| 収集中・表示先確定 | 点灯 | 点灯 | 収集・表示（緑・両灯点灯） |

状態は色だけでなく文字とツールチップでも伝えます。

収集器への接続失敗、チャット領域の未検出、表示接続の失敗、待ち行列の超過は別々に案内します。接続解除の理由はポップアップを開き直しても確認できるようにします。処理中の重複操作を防ぎ、発表用ページには操作通知を重ねません。完了通知は3.5秒で消えます。表示先の確定前は表示テストを無効にし、収集停止かつ表示先未指定のときだけ全体停止を無効にします。

最後の伝達時刻は「実コメントを表示経路が受け付けた時刻」を示します。アニメーションの完了時刻や、画面共有の成功時刻とは呼びません。

## 8. 受け入れ条件

以下を受け入れ条件とします。DOM・APIの検査、実ブラウザでの表示検査、実際のMeetでの投稿・共有確認を分けて実施します。

| ID | 確認する場面 | 合格条件 |
| --- | --- | --- |
| A01 | 開始前・停止後にチャットが追加される | 本文を収集しない |
| A02 | 同じMeetタブと別のWebタブを表示先にする | どちらも指定先だけに表示。フォーカス変更で宛先が変わらない |
| A03 | 収集元の候補が一覧にない | 現在のMeetタブを手動指定でき、別ドメインは拒否 |
| A04 | 表示テストと他参加者の新規投稿 | 両方を別々に確認。テスト成功を収集成功と扱わない |
| A05 | 開始時に確定投稿が存在する | 初期記録を表示しない。開始後に現れた過去記録は判別保証の対象外 |
| A06 | pending投稿が確定する／IDがない | 確定まで保留し、DOM置換・属性解除後に一度配送。IDなしは配送しない |
| A07 | 同文の別投稿、同じIDの再受信、本文編集 | 別IDは別投稿。保持範囲内の同一IDや既処理要素は再配送しない |
| A08 | 表示先未指定中の投稿、表示先切り替えの失敗 | 後から一括再生しない。切り替え失敗時は旧表示先を維持 |
| A09 | 会議変更、表示先再読み込み、全体停止 | 第5.4節の状態遷移。停止後に古い処理が状態を戻さない |
| A10 | 表示モード変更、待ち行列超過、期限切れ | 旧表示を消す。超過を通知。右下は最新6件・20秒の初期値を満たす |
| A11 | 本文や名前にHTML風文字列を入れる | コードを実行せず文字列で表示 |
| A12 | 表示先ページから本文を読もうとする | 親DOM・URL・windowメッセージに本文がなく、iframe内の直接読み取りが拒否される |
| A13 | 表示用iframeの複製、接続差し替え、別サイトへの移動 | 既存の本文や待ち行列を取得できず、別サイトへ本文を渡さない |
| A14 | ページ操作、全画面、iframe削除、無応答 | クリックとフォーカスを妨げず、失敗を案内。待機を無制限に続けない |
| A15 | 保存領域・ログ・外部通信を調べる | 本文と発言者名を拡張ストレージに保存・外部送信しない。コンソールには第6節の診断情報が出力される |
| A16 | 実Meetの別参加者から新規投稿し、画面共有する | 発表者の表示と共有受信側の表示を、それぞれ実際に確認 |
| A17 | 収集停止中に表示先を確定して表示テストを実行する | テストは表示され、収集は始まらない。ポップアップは右灯のみ点灯し、ツールバーは停止アイコン |

テスト用に追加した権限で動作することと、製品の`activeTab`操作で動作することは分けて確認します。

## 9. 制約

収集はMeetの非公開DOMに依存します。Googleの公開APIによる取得ではなく、UI変更によって収集できなくなる可能性があります。子iframeや別オリジンChat内の本文は収集しません。

開始後に読み込まれた過去記録と新規投稿の完全な区別、保持範囲外の重複防止、配送失敗した投稿の再送は保証しません。発言者名を取得できなければ「参加者」と表示します。名前が後から補完されても、表示済みの行は更新しません。

全サイト・全画面要素・Chromium派生ブラウザでの動作は保証しません。表示先サイトが表示面を削除・非表示にすることや、画面共有・録画への写り込みは防ぎません。表示テストや状態アイコンは、参加者側の共有画面での表示成功を示すものではありません。
